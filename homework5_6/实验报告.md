# 实验报告：基于OpenFHE的CKKS全同态加密卷积实现与优化

## 1. 实验目的

1. **作业5**：使用开源全同态加密库（OpenFHE，CKKS方案），对4×4输入和3×3卷积核（步长1，无填充）实现密文下的卷积运算，并验证结果正确性。
2. **作业6**：采用“打包→旋转→累加”策略，探索本次卷积实现中的旋转次数是否达到理论最小值，并给出优化分析。

## 2. 实验环境

- **操作系统**：Ubuntu 22.04 (VMware虚拟机)
- **编译器**：GCC 13.3.0
- **FHE库**：OpenFHE (commit 1.5.1)，从源码编译安装
- **编程语言**：C++17
- **硬件**：x86_64，4核CPU

## 3. 实验原理

### 3.1 CKKS方案与SIMD打包

CKKS方案支持将多个实数打包到一个密文中（Single Instruction Multiple Data），通过编码将向量映射到多项式环上的槽位。本实验将4×4=16个输入元素展平后打包进一个密文的16个槽位。

### 3.2 “打包→旋转→累加”卷积策略

- **打包**：将输入矩阵行优先展平为向量，编码为明文并加密。
- **旋转**：对密文进行循环移位（`EvalRotate`），使不同位置的输入元素对齐到同一槽位。
- **累加**：将旋转后的密文乘以对应卷积核权重，再累加所有乘积，得到输出卷积结果。

对于卷积核大小为 \( k \times k \)，每个输出位置需要累加 \( k^2 \) 个乘积。通过一次旋转并累加，可以同时计算出所有输出位置的对应项。

### 4.3 卷积实现

#### 偏移量设计

在4×4输入上滑动3×3卷积核（步长1，无填充），得到4个输出位置（2×2）。对于每个位置，涉及的输入索引（行优先）为：

- 窗口(0,0)：{0,1,2,4,5,6,8,9,10}
- 窗口(0,1)：{1,2,3,5,6,7,9,10,11}
- 窗口(1,0)：{4,5,6,8,9,10,12,13,14}
- 窗口(1,1)：{5,6,7,9,10,11,13,14,15}

对应的9个偏移量（相对于窗口左上角）为：{0,1,2,4,5,6,8,9,10}，与卷积核权重一一对应。

#### 核心代码

```cpp
std::vector<int> offsets = {0,1,2,4,5,6,8,9,10};
Ciphertext conv_result;
bool first = true;
int rotation_count = 0;

for (int k=0; k<9; ++k) {
    Ciphertext rotated;
    if (offsets[k] == 0)
        rotated = ciphertext;
    else {
        rotated = cc->EvalRotate(ciphertext, offsets[k]);
        rotation_count++;
    }
    auto weighted = cc->EvalMult(rotated, kernel[k]);
    conv_result = first ? weighted : cc->EvalAdd(conv_result, weighted);
    first = false;
}
```

经过9次迭代（实际旋转8次），`conv_result`的槽位0~3即为四个卷积结果。

### 4.4 验证方法

解密 `conv_result`，提取前4个槽位的实部，与明文卷积结果（手动计算）比较，允许误差 \(10^{-5}\)。

## 6. 旋转次数理论最小值分析

### 6.1 下界推导

对于 \( k \times k \) 卷积核，共有 \( k^2 \) 个权重，每个权重对应一个固定的空间偏移。为了将输入中所有与该权重相乘的元素对齐到同一累加槽位，必须对原始密文进行至少一次旋转（偏移0除外）。因此：

- 若偏移0的权重存在（一般卷积核中心），所需最少旋转次数 = \( k^2 - 1 \)。
- 若偏移0不存在（例如偶数大小卷积核），则为 \( k^2 \)。

本次为3×3核，偏移0存在，故理论最小旋转次数 = 9 - 1 = 8。

### 6.2 本实验达到最优

本实现仅对原始密文进行旋转，且每个非零偏移只旋转一次，未引入额外旋转（如结果提取、掩码操作）。因此，实际旋转次数 = 8，与理论下界一致，**达到最小值**。

## 7. 讨论与注意事项

1. **旋转方向**：实验中采用正偏移 `EvalRotate(ciphertext, offset)`，实际效果正确。若使用负偏移可能导致对齐错误，应基于库的旋转定义选择合适方向。
2. **Ring Dimension**：新版OpenFHE强制安全标准，需设置 `RingDim` ≥ 32768，否则抛出异常。
3. **精度**：CKKS为近似加密，但本实验误差为0，可能是由于整数输入和低深度操作，实际一般会有微小误差。
4. **可扩展性**：本方法可推广至更大输入和卷积核，但旋转次数随 \( k^2 \) 增长，需考虑更高级优化（如折叠旋转、多密文打包）。

## 8. 结论

- **作业5**：成功利用OpenFHE库实现了CKKS方案下的4×4输入与3×3卷积核的密文卷积，结果与明文一致，验证了正确性。
- **作业6**：通过“打包→旋转→累加”策略，本实现的旋转次数（8次）达到了理论最小值（8次），证明了优化的有效性。

本实验深入理解了全同态加密中SIMD操作和卷积的密文实现，为更复杂的隐私保护机器学习应用奠定了基础。
